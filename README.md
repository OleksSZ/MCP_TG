# Telegram core и MCP (только чтение)

Одна точка входа в Telegram для всех проектов на сервере. **Ядро** держит единственную сессию аккаунта и постоянно подключено. Проекты и Claude получают от него только то, что им разрешено.

```
                     Telegram (одна сессия, не «в сети»)
                                  │
                       tg-core (пользователь tgmcp)
                       сеть только к адресам Telegram
                                  │
              /run/tg-core/<клиент>/core.sock
      ┌──────────────┬────────────┴──────────────┐
   claude            parser                  monitor
      │             (Docker)                (на сервере)
   tg-mcp (tgmcp-web, без сети) ← Caddy ← claude.ai
```

## Зачем одно ядро
- **Одна сессия** вместо отдельной у каждого проекта.
- **Новые сообщения приходят пушем**, проекты не опрашивают Telegram.
- **Общие лимиты и общая пауза при FloodWait**, кэш списка чатов.
- **Статус «в сети» не меняется**: запрос `UpdateStatus` запрещён.

## Проекты и их права
В `/etc/tg-mcp/config.toml` у каждого проекта свой блок. Блок говорит, **что** проекту можно. **Какие чаты** слушать, решает сам скрипт.

```toml
[clients.parser]
events = true      # подписка на новые сообщения, правки, удаления
read = true        # чтение истории (и дочитывание после простоя)
media = false      # изображения
export = false     # выгрузка на сервер
search = false     # поиск по всем чатам, карточки контактов, поиск диалога по номеру
# chats = [-100123]  # необязательно: ограничить проект этими чатами
```

- **Блок нужен один раз на проект:** по нему ядро создаёт сокет `/run/tg-core/parser/core.sock`. Сокет и есть пропуск проекта, токенов нет.
- **Новые чаты в конфиг не пишутся:** скрипт сам называет их в `core.watch(chats=[...])`.
- **Ядро ничего не хранит, пока чат никто не слушает.** Отключился скрипт — подписка исчезла.
- **Боты, служебные чаты Telegram, Избранное и `denied_chat_ids`** закрыты для всех.
- **Риск:** без `chats` взломанный проект может подписаться на любой твой чат, а с `read = true` ещё и читать историю. Отправлять он не может ничего.

Добавил блок — выполни `./deploy/install.sh ХОСТ`. Изменил права — достаточно `systemctl restart tg-core`.

`chat_id` можно узнать у Claude: «найди чат с ...».

## Подключение проекта
Скопируй в проект `client/tgcore_client.py`. Он работает только на стандартной библиотеке Python. Как получать сообщения, решает сам скрипт, ядро для этого менять не нужно.

```python
from tgcore_client import TelegramCore

core = TelegramCore("/run/tg-core/core.sock")  # путь внутри контейнера

# Вариант 1: ядро присылает каждое новое сообщение сразу
for event in core.watch(
    chats=[-1001234567890],          # какие чаты слушать (необязательно)
    pattern=r"Missed call|from \d+",  # регулярное выражение по тексту (необязательно)
    events=["new_message"],          # можно добавить "edited", "deleted"
    state_file="/data/tg-state",     # где помнить позицию между перезапусками
):
    handle(event["chat_id"], event["message"]["text"])

# Вариант 2: скрипт сам спрашивает новые сообщения раз в interval секунд
for event in core.watch(mode="poll", interval=300, chats=[-1001234567890], state_file="/data/tg-state"):
    handle(event["chat_id"], event["message"]["text"])
```

| | `mode="stream"` (по умолчанию) | `mode="poll"` |
|---|---|---|
| Когда приходит | сразу | раз в `interval` секунд, минимум 30 |
| Запросы к Telegram | никаких, пока ждёт | один запрос на каждый чат каждый раз |
| Правки и удаления | да | нет, только новые |

Предпочитай `stream`. Частый `poll` по многим чатам увеличивает риск бана.

- **Первый запуск начинается с текущего момента**, старые сообщения не выгружаются.
- **После перезапуска** скрипт сам дочитывает новые сообщения, пропущенные за время простоя (нужно `read = true`, не дальше 7 дней назад). Правки и удаления за время простоя не дочитываются.
- **Позиция хранится в `state_file`**: без него каждый запуск считается первым.

История доступна напрямую: `core.read_messages(chat_id, "2026-11-01", "2026-11-19")` (право `read`).

Поиск:
```python
core.search_chat(chat_id, "18882557090")   # в одном чате, по страницам (read)
core.search("18882557090")                 # во всех чатах (search)
core.contact_cards(limit=200)              # карточки контактов, телефон только цифрами (search)
core.find_by_phone("+1 888 255 7090")      # личный диалог, если номер виден аккаунту (search)
```
`find_by_phone` отвечает только на заданный номер: список телефонов собеседников ядро не отдаёт. Сами запросы поиска в аудит не пишутся.

Ещё о доставке:

- **Сам переподключается** после перезапуска ядра или обрыва.
- **Доставка «минимум один раз».** Сообщение считается обработанным, когда цикл просит следующее. Если проект упал посередине обработки, сообщение может прийти снова, поэтому отбрасывай дубли по `message["id"]`.
- **Удаления в личных чатах и обычных группах не приходят:** Telegram не сообщает, из какого чата удалено сообщение.

**Docker:** монтируй каталог, а не файл, иначе после перезапуска ядра связь потеряется:
```yaml
services:
  parser:
    volumes:
      - /run/tg-core/parser:/run/tg-core
```
Пользователь внутри контейнера должен совпадать с `socket_user`: это `root`, если в образе не задан `USER`.

**Без Docker:** проект подключается к `/run/tg-core/monitor/core.sock`. Запусти его под отдельным пользователем и укажи этого пользователя в `socket_user`.

Можно обойтись без библиотеки, достаточно `curl`:
```bash
curl --unix-socket /run/tg-core/monitor/core.sock http://core/v1/chats
curl -N --unix-socket /run/tg-core/monitor/core.sock 'http://core/v1/events?chats=-100123'
```

| Запрос | Право |
|---|---|
| `GET /v1/health` | любой клиент |
| `GET /v1/chats?query=` | любое право |
| `GET /v1/chats/{id}/messages?date_from=&date_to=&limit=&before_id=` | `read` |
| `GET /v1/chats/{id}/search?q=&limit=&before_id=` — поиск в одном чате | `read` |
| `GET /v1/search?q=&limit=` — поиск по всем чатам, со ссылками | `search` |
| `GET /v1/search/contacts?limit=` — последние карточки контактов | `search` |
| `GET /v1/phone/{номер}` — личный диалог с владельцем номера | `search` |
| `GET /v1/chats/{id}/messages/{msg}/image` | `media` |
| `POST /v1/exports`, `GET /v1/exports/{job}` | `export` |
| `GET /v1/events?chats=1,2&types=new_message` | `events` |

## Переезд проектов на ядро
Переводи по одному проекту:

1. Добавь проект в `config.toml` с минимальными правами и выполни `./deploy/install.sh ХОСТ`.
2. Замени в проекте Telethon на `tgcore_client.py`, проверь работу.
3. Удали у проекта файл сессии Telethon.
4. Завершь его старую сессию: **Telegram → Настройки → Устройства**.

Пока старые сессии не завершены, риск бана не снижается.

## Установка и обновление
Со своего компьютера:
```bash
cd /home/oleks/Addons
tar --exclude=venv --exclude=__pycache__ -czf - MCP_TG | ssh root@SERVER 'tar xzf - -C /root'
```
На сервере:
```bash
cd /root/MCP_TG && ./deploy/install.sh ХОСТ
tg-mcp-login     # только при первой установке: вход в Telegram
```

При обновлении с прошлой версии:

- сессия Telegram, подключение Claude и настройки сохраняются;
- в конфиг автоматически добавляется клиент `claude`.

Подключение Claude: в Claude нажми **Connect** у коннектора, на открывшейся странице введи код из `tg-mcp-pair`.

## Защита
| Угроза | Защита |
|---|---|
| Отправка, удаление, «прочитано», статус «в сети» | Белый список из 16 запросов Telegram API, всё остальное блокируется до отправки |
| Взлом проекта | Проект не может писать, у него нет ключа сессии. Чаты ограничены, только если в его блоке задан `chats` |
| Взлом MCP из интернета | Веб-часть работает под отдельным пользователем без сети, ключа и сессии, и ей доступен только сокет `claude` |
| Подключение чужого к Claude-коннектору | OAuth с одноразовым кодом из SSH, токены на 15 минут, повторное использование refresh-токена отключает Claude |
| Утечка через зависимость ядра | Сеть только к адресам Telegram, seccomp, `MemoryDenyWriteExecute`, без дампов памяти и swap |
| Переписка на диске | Сессия и позиция обновлений зашифрованы. События и выгрузки хранятся только в RAM |
| Перебор и массовые запросы | Общий лимит ядра плюс лимит на каждого клиента. Аудит без текста: `/var/lib/tg-mcp/audit.log` |

## Что не закрыто
- **Root и Docker:** взлом root или побег из контейнера дают доступ ко всему. Надёжнее всего отдельный VPS.
- **Хостер и резервные копии:** при отсутствии TPM снимки диска содержат и зашифрованную сессию, и ключ к ней.
- **Данные Claude уходят Anthropic:** всё, что прочитал коннектор, передаётся провайдеру модели.
- **Prompt injection:** текст сообщений пишут посторонние люди. Ни проекты, ни Claude не должны выполнять инструкции из сообщений.
- **Хост `sslip.io`:** его DNS контролирует третья сторона. Для постоянной работы лучше свой домен.

## Эксплуатация
| Задача | Команда |
|---|---|
| Состояние | `systemctl status tg-core tg-mcp.socket`, `journalctl -u tg-core` |
| Отключить Claude | `tg-mcp-revoke` |
| Отключить всё | `systemctl disable --now tg-core tg-mcp.socket 'tg-core-*.socket'` |
| Перезайти в Telegram | `tg-mcp-login` (ядро на это время останавливается) |
| Завершить сессию | Telegram → Настройки → Устройства |
